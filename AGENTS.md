# MooreMinecraft operator / development instructions

- Owner: Zigdon7. This monorepo stores all Saturn custom mods, updater source and release manifests.
- **After finishing a coherent change batch, run the relevant checks, commit and push it to this repository. Do not leave completed work only in a local checkout.** Push tested milestones throughout long work, not only at the final release. If auth or branch protection blocks a push, report it promptly and preserve the commit.
- Production Pumpkin is separate from staging. Do not deploy to production until explicitly authorized and stable. Current staging: port 25566, independent Survival Overworld, online authentication enabled.
- Never commit credentials, auth configuration, environment secrets, player data/worlds, private backups or local runtime caches.
- Pumpkin loads WASM, not Java server mods. Fabric code here is client-only. Bedrock compatibility must be tested separately.
- Plugin capability approval remains manual: relay any new requested permission and wait for owner approval. Owner approved fs.read.data and fs.write.data for staging Atlas and explicitly extended installation/these permissions to production on 2026-11-13. Relay any additional capabilities.
- Preserve existing data and rollback paths. Do not reset worlds, wipe player data or replace the production binary without explicit approval and backup.
- Every release must include exact target versions, artifact hashes and test evidence. Do not call headless layout tests actual in-game rendering proof.
- Public updater manifests pin exact release tags/assets, sizes and SHA-256 values. Never install arbitrary executables from a mod manifest; updater payloads are JARs only. Sole exception, owner-requested 2026-11-12: the Mod Manager may replace its own EXE from the `windows-updater` entry of `releases/staging/components.json` (fixed feed (production/components.json starting with owner-requested 0.3.0 on 2026-11-13; staging entry retained for legacy upgrade discovery), this repository's release downloads only, pinned version/size/SHA-256, upgrades only). Upload the release asset before updating that entry; changing it pushes the new EXE to every user. Keep staging and production channels separate.
- Atlas tests: mods/saturn-atlas/tests/run-local-suite.sh. Updater tests: dotnet run --project tools/mod-manager/Tests/Saturn.Manager.Tests.csproj.

- **Protected Pumpkin fix (owner, 2026-11-13):** every server-engine update must retain the eyeblossom Trail disconnect mitigation, or a verified upstream replacement. Follow `server-patches/pumpkin/EYEBLOSSOM-DISCONNECT.md` and run `check-eyeblossom-fix.py` on candidate source before building/promoting. Never blindly replace with a stock binary or drop this when promoting chunk-preload. Source patch alone is not runtime/deployment proof.
